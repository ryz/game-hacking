# Map style guide

How every floor map in this folder looks, so that all 30 maps read the same. The maps are generated by
`python3 tools/designtables/floormap.py N`; change the generator, never a map image by hand. When this guide and the
generator disagree, fix one of them in the same commit.

## 1. Principles

- **The game's data, nothing invented.** Every wall, door and square comes from the floor data. Interpretations
  (a special wall being a hidden door) live in the legend wording and the floor page, marked (inferred).
- **Readable without colour.** Every symbol is a letter or a line style as well as a colour, so a map works in
  print and for colour-blind readers.
- **Same legend everywhere.** The legend is printed in full under every map, even for symbols the floor does not use.
- **Quiet background, strong structure.** Walls and symbols are dark and bold; floor, grid and area numbers are light.

## 2. Canvas

| Element | Value |
|---|---|
| Orientation | north up; x east from 0 (left) to 15, y north from 0 (bottom) to 15 |
| Cell | 48 × 48 px, 16 × 16 cells; image about 810 × 1000 px including legend |
| Title | "Floor N (BNF)", bold 17 px, top left |
| Subtitle | one grey line under the title about random fights (see 4) |
| Axes | 0-15 under and left of the grid; under the axes: "x east -> y north ^ (the map wraps at its edges)" |
| Fonts | DejaVu Sans Bold 15 px (symbols), DejaVu Sans 11 px (numbers, notes, legend text) |
| File | `floor-NN.png` (two digits), next to `floor-NN.md` |

## 3. Palette and symbols

| What | How it is drawn | Colour (RGB) |
|---|---|---|
| Open floor | white cell, faint grid line | floor 255,255,255; grid 226,226,226 |
| No random fights (area 0) | light grey cell | 228,228,228 |
| Rock | dark grey cell | 70,70,70 |
| Wall | black line, 3 px | 0,0,0 |
| Door | wall line with a brown bar across its middle (18 × 6 px) | 170,100,30 |
| Special wall | red dashed line, 3 px (meaning: "probably a hidden door", inferred) | 220,0,0 |
| Damage zone | diagonal hatch | 232,128,128 |
| Anti-magic zone | dot grid (inferred meaning) | 90,110,220 |
| Both zone marks | hatch and dots, purple (no known effect) | 160,90,190 |
| Stairs up / down | **UP** / **DN** | green 0,110,0 |
| Guarded square | **G** | red 190,0,0 |
| Hidden spot | **H** | purple 120,60,160 |
| Event / one-shot event | **E** / **E1** (floor-specific events are E too) | blue 0,90,160 |
| Button panel | **B** | blue 0,90,160 |
| Corpse | **C** | brown 90,60,30 |
| Floor trap | **T** + kind: TP pit, TC chute, TF falling ceiling, TR rockfall, TV viper, TS spinner | orange 200,90,0 |
| Marker square | small grey dot (automap memory, inferred; no effect on play) | 90,90,90 |

Symbols sit in the top-left corner of their cell with a 2 px white outline, so they stay readable on hatching.

## 4. Encounter areas

- If one area covers at least 80% of the open squares, the subtitle names it ("random fights: encounter area 30")
  and only squares with a different area get a grey number (bottom-left corner).
- Otherwise every open square gets its number, and the subtitle says so.
- Floors without random fights say "no random fights".

## 5. What a map does not show

- Event details, trap strength, hidden-spot difficulty, monsters: these belong in the floor page's tables, keyed by
  (x, y).
- Routes, the party's position or arrows: a map is a reference, not a walkthrough. A floor page may add its own
  annotated copy if a route needs explaining, named `floor-NN-<topic>.png`.

## 6. Changing the style

Change `tools/designtables/floormap.py` and this guide together, regenerate every published map
(`for n in ...; do python3 tools/designtables/floormap.py $n; done`), and look at floor 1 (mixed areas), floor 11
(damage zone) and floor 28 (all zone kinds, 120+ traps) before committing: together they use every element.
